## 2. Executive Summary

This document defines a new slot game project. Four facts are confirmed: the project is a slot game; it will support desktop PCs; desktop distribution will be through Steam; and it will support Meta Quest 3 virtual reality.

Beyond these facts, most product-level decisions remain open: game engine, programming language, slot mechanics and parameters (reel configurations, paylines, RTP, volatility, betting structure), regulatory classification, and any online or multiplayer scope. This document records the confirmed facts, distinguishes proposals from approved requirements, and marks undecided items as TBD. Section 13 lists the questions that require stakeholder decisions.

## 3. Project Vision

**Confirmed:** The project delivers a slot game playable on desktop PCs (distributed via Steam) and on Meta Quest 3 virtual reality.

**Proposal (draft, pending approval):** A slot game that delivers a coherent core gameplay experience on desktop PCs and on Meta Quest 3 VR, based on a shared game design with platform-appropriate interaction.

The final vision statement will be ratified as part of project charter sign-off (Section 14).

## 4. Project Objectives

The following objectives are **proposals** and require stakeholder approval:

1. Deliver a functioning slot game build for desktop PCs, distributable through Steam.
2. Deliver a functioning slot game build that supports Meta Quest 3 VR.
3. Provide a consistent core gameplay experience across both confirmed platforms.
4. Resolve all technology decisions (OQ-2, OQ-3) before detailed design begins.
5. Define the slot game parameters through an approved design specification (OQ-4).

## 6. Project Scope

**In scope (confirmed):** development of a slot game; desktop PC support; Steam distribution of the desktop build; Meta Quest 3 VR support.

**Proposed in scope (pending approval):** a single-player, locally played gameplay experience.

**Proposed out of scope for the initial release (pending approval; see OQ-6 and OQ-7):** multiplayer features; online services (accounts, leaderboards, cloud saves); monetization (real-money wagering, in-app purchases, advertising).

**Undecided:** mobile (smartphone/tablet) support — TBD; console support — TBD; VR headsets other than Meta Quest 3 — TBD.

## 8. Non-Functional Considerations

- **Performance.** Performance targets (frame rate, latency, load times) are TBD. The Quest 3 build must meet frame-rate requirements appropriate to VR comfort; specific values are to be defined in the design phase.
- **Usability.** Desktop and VR interaction models differ; usability requirements are to be defined per platform (TBD).
- **Localization.** Primary language and any additional languages are TBD (OQ-11).
- **Accessibility.** Proposal to assess accessibility requirements (input alternatives, display settings) during design; scope TBD.
- **Security and privacy.** Out of scope to the extent online services are not included; to be revisited if online features are added (OQ-6).
- **Legal and regulatory.** The game's classification (real-money gambling versus entertainment-only) is undecided and materially affects compliance obligations, target audience, age rating, and platform policies (OQ-5). This is treated as a critical decision, not a default assumption.

## 9. Technical Constraints

1. No game engine has been selected; the engine selected (OQ-2) must support both confirmed platforms.
2. No programming language or toolchain has been selected (OQ-3).
3. The technical approach must support Steam distribution on desktop PCs and native operation on the Meta Quest 3, a standalone headset running its own operating system.
4. Supported desktop operating system(s) are TBD (OQ-1); this affects build targets and the testing matrix.
5. Whether a shared codebase or separate implementations will be used across platforms is undecided (OQ-14).

## 11. Risks

| # | Risk | Potential Impact | Proposed Mitigation |
|---|---|---|---|
| R-1 | Undecided regulatory classification (real-money vs. entertainment). | Rework, store rejection, jurisdictional restrictions. | Resolve OQ-5 early; legal review before detailed design. |
| R-2 | Two platforms with very different hardware (desktop PC, standalone VR headset). | Cost and schedule overrun. | Early technology decisions (OQ-2, OQ-3); early prototypes on both platforms. |
| R-3 | Delay in technology selection. | Downstream decisions blocked. | Set decision deadlines for OQ-2 and OQ-3. |
| R-4 | VR comfort and interaction unknowns. | Poor Quest 3 user experience. | Early VR playtests; defined comfort guidelines. |
| R-5 | Third-party platform policy changes (Steam, Meta). | Distribution constraints. | Monitor platform policies; keep design flexible. |
| R-6 | Scope ambiguity from undecided product parameters. | Rework and disputes. | Require the approved slot design specification before detailed design (OQ-4). |

## 12. Assumptions

Assumptions are accepted as true for planning purposes but are not verified. If any assumption proves false, this document will be revised.

- **A-1:** The confirmed facts in Section 5 remain valid throughout the definition phase.
- **A-2:** Answers to the open questions in Section 13 will be provided by the Project Sponsor or a designated delegate within the definition phase.
- **A-3:** An authoritative slot design specification will be produced by a designated owner before detailed design begins.
- **A-4:** Development and test hardware for both platforms will be available to the team (procurement responsibility TBD).
- **A-5:** Until OQ-5 is resolved, planning assumes no real-money wagering and therefore no immediate gambling regulatory obligations. This assumption requires validation by the Project Sponsor.

## 13. Open Questions

The following questions require stakeholder decisions; owners are TBD unless otherwise stated.

- **OQ-1.** Which desktop operating system(s) does "desktop PC" cover (Windows, macOS, Linux, or a subset)?
- **OQ-2.** Which game engine will be used, and what are the selection criteria?
- **OQ-3.** Which programming language(s) and toolchain will be used?
- **OQ-4.** Who owns the slot design specification (reel configuration, paylines/ways, RTP, volatility, betting structure), and when will it be approved?
- **OQ-5.** Is the game intended for real-money play (regulated gambling) or for entertainment-only (non-monetary) purposes? Which jurisdictions are targeted?
- **OQ-6.** Are multiplayer and online services confirmed out of scope for the initial release?
- **OQ-7.** Is monetization confirmed out of scope for the initial release?
- **OQ-8.** What is the distribution channel for the Meta Quest 3 build (for example, the Meta Quest Store)?
- **OQ-9.** What is the desktop input scheme (keyboard/mouse, controller, or both)?
- **OQ-10.** What is the Quest 3 interaction model (handheld controllers, hand tracking, or both)?
- **OQ-11.** Which languages will the game support?
- **OQ-12.** Who is the target audience, and what age rating is intended?
- **OQ-13.** What are the budget, schedule, and team composition?
- **OQ-14.** Is a shared codebase across both platforms intended?
- **OQ-15.** Which Steamworks features (store page, achievements, etc.) should be enabled?
